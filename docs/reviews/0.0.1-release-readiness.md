# Release Readiness for Em See Pea Server 0.0.1

Date: 2026-08-28

This review covers `@emseepea/server` for npm publication. It also records
source-check results for the private `@emseepea/react` and
`@emseepea/tailwind` workspaces.

## What Works

- Fastify-first Model Context Protocol (MCP) `2026-07-28` servers over
  Streamable HTTP
- public tools and tools that require sign-in
- separate public and backend data checks with explicit mapping
- public resources, resource patterns, prompts, and optional suggestions
- bounded progress updates for local examples
- native HTML and optional React form renderers
- one ready-to-import Tailwind stylesheet
- anonymous server discovery and tool listing, even when a tool requires
  sign-in

## What Has Passed

- architecture review
- checks on Node.js 22 and 24
- raw HTTP and official MCP client tests
- clean package installation and import tests
- light, dark, high-contrast, keyboard, focus, reflow, and browser
  accessibility checks for both UI examples
- an independent runtime screen-reader simulation of ready, invalid, busy, and
  finished states in both UI examples, plus the React failed-request state
- a packed-package test that installs the prospective server package and calls
  a public tool through its HTTP endpoint
- a local language-model check of all eight examples, with three answers and
  three independent judgments for each example
- dependency audit with no known vulnerabilities
- inspection of the server package and both private UI workspaces

The screen-reader review used the browser accessibility tree, focus, and live
regions. It was not a VoiceOver, NVDA, or JAWS run. The local language-model
result does not authorize publication; GitHub must repeat it for the commit
being published.

## What Must Pass Before Publishing

The commit being published must pass:

- `npm test`
- the JSON boundary benchmark
- the dependency audit
- package-content inspection
- package checksums and dependency-list generation
- three language-model answers and three independent judgments for every
  example

The language-model check uses the pinned Claude command-line package and
`claude-sonnet-4-6` through the existing Claude subscription. Local model runs
do not authorize publication.

After publication, automation must confirm that:

- the server package uses the `next` tag
- the `latest` tag is unchanged
- the downloaded server package matches the inspected package
- the server package installs and imports successfully

## Not Included Yet

- tools that write data, transactions, or retries
- record-level or organisation-level access decisions
- framework-managed rules for outbound HTTP calls
- large result pages or configurable caching
- production streaming through proxy servers
- saved sessions, subscriptions, replay, or reconnect recovery
- shared state across more than one server instance
- full coverage of the active MCP server protocol
- deployment of an adopter's server
