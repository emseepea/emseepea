## What Changes for Users

Server authors can opt into deterministic capability discovery from one local
directory at startup. Capability modules use a documented filename convention,
export one default factory, and enter the same immutable checked registries as
explicitly registered tools, resources, and prompts. Malformed, mismatched,
conflicting, and unsafe entries stop startup before network exposure.

Mapped tool output now rejects undeclared top-level data properties during
TypeScript checking. Runtime validation of public input, backend commands,
backend results, and public output remains unchanged.

All eight maintained examples and their initializer packages now demonstrate
startup discovery. The examples remain the sole maintained template source.
The React package release updates its server dependency for this batch.

## Evidence Boundary

- Discovery is optional. Explicit registration remains supported.
- Discovery reads one directory once at startup. It does not recurse, watch the
  filesystem, or change a running catalogue.
- The mapping change adds a TypeScript check for undeclared top-level output
  properties. Runtime schemas remain the authority at the untrusted boundary.
- This release does not claim full MCP profile conformance or remove the limits
