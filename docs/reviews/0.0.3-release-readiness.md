# Prepublication Review for Server 0.0.3 and Testing 0.1.0

Date: 2026-08-31

**Publication is pending.** This record covers the planned paired release of
`@emseepea/server@0.0.3` and `@emseepea/testing@0.1.0` under the `next` tag.
It is not evidence that either version has been published or qualified.

## What Changes for Users

Server authors can add:

- requests for more client input before a final result
- checked request headers and richer discovery details
- bounded catalogue pages and cache instructions
- public progress updates through a trusted proxy
- optional request telemetry, dependency readiness, and shutdown flushing

Testing users can write executable JavaScript cases in `eval/`, separate from
ordinary tests in `test/`. Cases can make several MCP calls and use custom
assertions. YAML cases must be migrated to `semanticTest` from
`@emseepea/testing/semantic`; Promptfoo is no longer a dependency.

The [coverage guide](../protocol-coverage.md) describes supported behaviour and
remaining gaps. This is not a full-protocol release.

## Required on the Publishing Commit

- Node.js 22 and 24 builds, tests, package checks, and dependency audits.
- CI-only JSON performance and proxy-load checks, with unchanged limits.
- All eight examples checked with the pinned Claude CLI and model: three fresh
  answers and nine independent judgments per case, with no semantic retries.
- Evidence tying each trial to the actual MCP operations and returned data.
  Model credentials remain isolated; redacted CI evidence is kept for 14 days.
- Independent release-risk review within the project's appetite.

The workflow skips real-model checks while it is only preparing a release PR.
A successful PR-update run is not semantic qualification. The
[AI-understanding risk](../risks/R005-semantic-qualification-misses-wrong-meaning.active.md)
remains unacceptable for publication until every example passes on the
publishing commit.

## Required After npm Publication

Both packages must have their intended `next` versions, unchanged `latest`
tags, and trusted-publishing provenance tied to the publishing commit.
Downloaded packages must match the inspected archives and pass installation,
dependency audit, signature checks, public imports, and MCP checks.

Only then may automation create the Git tags and GitHub releases. Direct npm
and GitHub readback must confirm completion. Version 0.0.2 reached npm but
failed later verification; it is not a precedent for calling a release complete.

## Not Included

- Full MCP coverage, subscriptions, reconnect, replay, or slow-reader backpressure.
- Deployed streaming tools that require sign-in, or a guarantee for every proxy.
- Publication of the React and Tailwind packages. They and the examples remain
  public MIT source; native HTML rendering remains part of the server package.
- A built or published website. Its design decisions are approved separately.
